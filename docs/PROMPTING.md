# Как ставить задачи агенту

Проверено по официальным источникам OpenAI 16.10.2026: [постановка задач](https://learn.chatgpt.com/docs/prompting), [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Полезно назвать результат, дать относящийся к нему контекст, ограничения и способ проверки. Постоянные правила держать в AGENTS.md, конкретный этап — в текущем запросе. Не нужна длинная роль вроде «ты лучший архитектор мира»; важнее проверяемые требования.

Ниже — адаптированные для этого проекта запросы, а не цитаты документации. Они не гарантируют безошибочный результат: реальные сборки и проверки обязательны.

Актуальный запуск этого проекта: [пакет агентов](../harness/README.md), [рекомендации для двух моделей](../harness/PROMPTING.md), [официальные источники](../harness/SOURCES.md). Шаблоны ниже поясняют общие принципы; для выполнения использовать Hxx и готовые запросы из harness/prompts, чтобы не обойти checkpoints и gates.

## Планирование нового приложения

```text
Мне нужен подробный план Android-приложения [назначение].
Пользователь и основные сценарии: [описание].
Обязательные ограничения: [локальность, версии Android, безопасность,
восстановление, доступность, дизайн, доступные устройства].
Прочитай AGENTS.md и README.md проекта. Проверь актуальные технические
решения по первичным источникам. Задай только вопросы, ответы на которые
меняют архитектуру; по остальным явно предложи разумные допущения.
Подготовь требования, границы MVP, стек с обоснованием, модель угроз,
схему ключей и восстановления, модель данных, структуру модулей,
этапы с зависимостями и критериями приёмки, проверки и оценку диапазоном.
Отдели подтверждённые требования, рекомендации и открытые решения.
Можно создавать документы, структуру и макеты; реализацию приложения
пока не начинать. В конце проверь документы на противоречия и дай ссылки.
```

## Реализация одного этапа

```text
Реализуй этап [Hxx] из harness/PLAN.md проекта «Моя жизнь» по его карточке.
Используй harness/PROTOCOL.md, подтверждённый профиль модели и gate validator.
Сначала прочитай корневой и применимые модульные AGENTS.md/README.md,
docs/STATUS.md и относящиеся спецификации. Не меняй границы offline/security.
Уточняй только существенную неопределённость; рутинные решения принимай сам.
Доведи этап до указанного gate. Используй только синтетические данные.
Выполни обязательные проверки, исправь относящиеся к этапу ошибки,
обнови STATUS.md и knowledge/ERRORS.md. Не переходи к следующему этапу.
Отчёт: что работает, как проверено, что не проверено и что блокирует gate.
```

## Ревью плана до реализации

```text
Проведи read-only ревью docs/PRODUCT.md, ARCHITECTURE.md, SECURITY.md,
DATA_MODEL.md, IMPLEMENTATION_PLAN.md и TESTING.md.
Найди противоречия между локальным хранением, отдельным PIN, биометрией,
фоновыми напоминаниями, системными копиями и восстановлением на новом телефоне.
Для каждого замечания дай риск, конкретное место, сценарий проявления
и минимальное исправление. Различай обнаруженную ошибку и вопрос без данных.
Не редактируй приложение и не подставляй фиктивные результаты тестов.
```

## Проверка готовности

```text
Проверь gate этапа [номер] на текущем состоянии проекта.
Прочитай инструкции и TESTING.md. Запусти доступные обязательные проверки,
не используй личные данные. Для каждой укажи PASS/FAIL/NOT RUN и основание.
Успех сборки не считать успехом восстановления или безопасности.
Если инструмента/устройства нет, точно укажи недостающую проверку.
Запиши найденные ошибки в базу знаний; предложи следующий конкретный шаг.
```

## Дизайн

```text
Возьми утверждённую компоновку «Фокус» из design/dashboard.html. Сохрани выбранную
тему «Бумага» (белый и графитовый), спокойную типографику и меню слева
по кнопке ☰. Главная: дела, напоминания, недавние места и записи.
Доработай только [экраны/сценарий]. Покажи empty/error/locked состояния,
крупный шрифт и ширину 320 dp. Не добавляй сеть, реальные фотографии
или пароли. Обнови токены и проверяемый локальный макет.
```

Передавать агенту настоящие PIN, пароли, ключи подписи и содержимое личной базы не нужно. Для ошибки достаточно обезличенного сценария, версии, кода ошибки и тестового примера.
