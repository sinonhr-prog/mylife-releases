# Проверки и выпуск

## Сейчас

Проверяется только проектный пакет и макеты. Android-тестов и Gradle пока нет. Свежие результаты записываются в STATUS.md; будущие gates ниже не являются выполненными.

## Матрица

- Android 10/API 29: нижняя граница, PIN/биометрия, хранилища, выбор фото и уведомления.
- Android 12/API 31: ограничения фоновой работы и backup rules.
- Android 13/API 33: разрешение уведомлений и clipboard.
- Последняя стабильная Android на момент реализации: современный SDK, edge-to-edge, 16 KB страницы с native dependencies.
- Vivo X200 Pro mini владельца: фактические Android/оболочка/patch level фиксируются только после проверки устройства.
- Другой чистый эмулятор/телефон: восстановление без исходного Keystore. Одна только переустановка на исходном телефоне не заменяет этот тест.
- Экран 320/360/390/430 dp, масштаб шрифта 100/130/200%, TalkBack; планшеты не цель MVP, но без критических падений.

## Уровни

Для дашборда/меню дополнительно: открытие по ☰, закрытие по Back/Escape и затемнению, выбор всех категорий, возврат фокуса, отсутствие попадания фокуса под меню, прокрутка маленького экрана. При открытии меню из сейфа сессия закрывается. Проверить сортировку и пустые блоки, исключение vault/архива, lastVisitedAt отдельно от updatedAt, createdAt отдельно от даты редактирования. Макет проверяет только навигационное поведение; авторизация и выборки требуют будущих Android-тестов.

1. Unit: валидация рейтинга/URL/денег, даты и повторения, состояния сессии, идемпотентность планирования, генератор паролей.
2. Security unit + instrumentation: известные криптовекторы, wrong key/PIN/tag/nonce, повтор nonce запрещён, смена PIN, потеря/инвалидация Keystore, биометрический отказ, независимость сейфа.
3. Storage: реальные SQLCipher/Room, WAL и служебные файлы, все миграции из поддержанных версий, FKs/индексы, транзакции, нехватка места, прерывание записи файла, orphan cleanup.
4. Backup: другой телефон, неверная фраза, подмена заголовка/AAD, повреждённый/обрезанный архив, огромные KDF/размеры, path traversal, disk full, cancel, crash до/после переключения поколения. Каждая неудача сохраняет текущую базу.
5. UI: основные CRUD-сценарии, empty/loading/error/locked, поворот, process death, клавиатура, большой шрифт, доступность без ориентации только на цвет.
6. Device: airplane mode, отсутствие сетевого трафика/INTERNET, screenshot/recents, уведомления, clipboard, Photo Picker, перезагрузка, Doze, battery restrictions Vivo, отказ в разрешениях.
7. Release: merged manifest, запрет системного backup для поддержанных транспортов, debug=false, компоненты/permissions, зависимости и лицензии, подпись/обновление, hash, performance.
8. Updates: парсинг update.json, валидация полей, потоковое скачивание APK, сверка SHA-256, проверка сертификата подписи (certificate pinning), защита от понижения версии (downgrade prevention), отказ в установке при несовпадении хэша/подписи, сохранение зашифрованных баз и сессий при установке V1 → V2.

## Обязательные security gates

- Реальные пароли запрещены до полного round-trip копии и ревью ключей/архива.
- На диске, в logcat, clipboard preview, уведомлениях и saved state нет незапрошенных открытых секретов.
- Передача главной сессии не позволяет расшифровать сейф.
- PIN-protection учитывает offline guessing и device-bound фактор; лимит попыток не заявлен как аппаратный.
- Биометрия привязана к crypto operation; замена callback «успех» не должна выдавать ключ.
- Экспорт на новом устройстве открывается только фразой, без старого Keystore и без PIN старого телефона.
- Автокопии/перенос проверены отдельно от ручного архива. Отсутствие доступа к OEM-проверке — известное ограничение, не PASS.
- MASVS-сопоставление включает STORAGE, CRYPTO, AUTH, PLATFORM, CODE, PRIVACY и применимые RESILIENCE; отсутствие посторонней сети проверяется отдельно, а не считается автоматически доказанным.
- Обновлятор проверяет криптографическую подпись и SHA-256 скачанного APK до передачи PackageInstaller; установка неподписанного, повреждённого или подписанного чужим ключом APK блокируется.
- Сетевой обмен ограничен исключительно allowlist GitHub (api.github.com, CDN релизов); запросы не содержат личных данных, параметров баз, токенов или секретов.

## Производительность

Release build, фиксированный seed синтетических данных, минимум 20 повторов с отчётом p50/p95. Холодный старт считать до PIN, KDF отдельно. Датасеты 10k записей, 1k товаров с фотографиями, архив до 1 ГБ. Проверять memory/GC/scroll и отсутствие OOM. Цели в ARCHITECTURE.md — исходные бюджеты, корректируются только с измерением и объяснением.

## Будущие команды

Из `apps/android` после bootstrap: `./gradlew.bat :app:assembleDebug :app:lintDebug testDebugUnitTest`, затем `./gradlew.bat connectedDebugAndroidTest`. Задачи `ktlintCheck`, benchmark и release gates добавляются и проверяются на этапе 1. Не запускать несуществующие команды и не считать отсутствие SDK прохождением теста.

Для релиза запускать также lint/tests соответствующего release variant, проверку подписи и manifest из собранного APK. Точный единый скрипт gate создать после появления реального build graph.

## Доказательства

Отчёт: дата, commit или hash набора исходников, версия APK, устройство/API, команды, PASS/FAIL/NOT RUN, длительность, исправленные дефекты и остаточные ограничения. Только синтетические данные. Ошибки — в knowledge/ERRORS.md. Скриншот макета и успешный build не доказывают безопасность и не заменяют тесты устройства.
