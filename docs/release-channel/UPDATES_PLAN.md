# План встроенных обновлений

Дата: 17.10.2026. Статус: план, а не реализованная функция.

## Ожидаемый результат

Пользователь скачивает первый APK из GitHub Releases. В нём уже есть экран «Настройки → Обновления». Следующий APK скачивается с этого экрана и устанавливается поверх приложения через системное подтверждение Android. Данные сохраняются проверенными миграциями; приложение не удаляется.

## Этапы

1. **Канал распространения.** Создать публичный `sinonhr-prog/mylife-releases` и разместить документы. APK публиковать после следующих этапов.
2. **Контракт и защита.** Зафиксировать постоянные applicationId, ключ подписи, versionCode и формат metadata. Оформить узкое исключение из офлайн-политики для обновлений; личные данные, облачная синхронизация и аналитика не входят в исключение. Согласовать документацию и проверки до изменения manifest.
3. **Обновлятор.** Экран с текущей/новой версией, описанием, проверкой по кнопке, прогрессом, отменой и повторной попыткой. UI → ViewModel → repository interface → отдельный сетевой клиент без доступа к хранилищу личных записей. Новый Gradle-модуль создавать только при необходимости.
4. **Загрузка и установка.** HTTPS, проверка каждого redirect по allowlist, таймауты и лимит размера, приватный временный cache, потоковая загрузка вне главного потока. Проверить SHA-256 и криптографическую подпись APK, пакет/версию/совместимость. Обработать разрешение установки из этого приложения, отмену и системный результат PackageInstaller. При необходимости пользователь отдельно разрешает этому приложению установку обновлений.
5. **Проверки.** Установить V1, создать синтетические данные, обновить до V2 тем же ключом. Проверить версию, записи, миграции и авторизацию. Выполнить на API 29 и реальном целевом телефоне. После проверок опубликовать первый APK с обновлятором.
6. **Повторяемый выпуск.** Последующие версии проходят тот же процесс; при необходимости добавить автоматизированную публикацию готовых подписанных файлов.

## Политика сети

Сначала только ручная проверка обновлений. Автопроверка при запуске — возможный следующий шаг с отдельной настройкой, без постоянного polling. Для публичного GitHub токен не нужен; необходимы кеширование, backoff и обработка лимитов API.

INTERNET является разрешением на всё приложение: ограничение доменов обеспечивается архитектурой и проверками кода, а не отдельной системной песочницей. Обновлятор не получает записи, фото, PIN или ключи. GitHub/CDN видит технические данные соединения, включая IP. Cleartext, произвольные URL, удалённые изображения, WebView и сетевые SDK аналитики не допускаются.

## Обязательные отрицательные сценарии

- Чужой пакет/сертификат, неверный hash, усечённый APK, откат версии.
- HTTP и redirect на неразрешённый хост, подмена metadata, повреждённый JSON.
- Prerelease в stable, несовместимый Android, отсутствие релиза и подходящего asset.
- Нет сети, таймаут, HTTP 403/429, нехватка места, отмена/прерывание процесса.
- Отказ в разрешении установки и отмена системного диалога: старая версия работает.
- Сетевые запросы и логи не содержат синтетического содержимого записей; backup/перенос остаются отключены.

## Критерий готовности

Проверен реальный сценарий скачивания первого APK с GitHub и обновления до следующего через приложение с сохранением синтетических данных. Одного наличия APK или документов недостаточно. Ключи подписи сохраняются отдельно и резервируются владельцем. Ротация ключа требует отдельного проекта и проверки signing lineage.
