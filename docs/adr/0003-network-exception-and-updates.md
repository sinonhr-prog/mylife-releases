# ADR 0003: Узкое сетевое исключение и канал встроенных обновлений через GitHub Releases

Статус: выбрано архитектурное решение по поручению владельца от 17.10.2026.

## 1. Контекст

Приложение «Моя жизнь» изначально проектировалось по строго автономному принципу («без интернета / без сетевых разрешений»). Все личные данные (заметки, списки покупок, места, напоминания, изолированный сейф с паролями, зашифрованные файлы) создаются, обрабатываются и хранятся исключительно локально на устройстве пользователя.

Для распространения приложения без использования сторонних коммерческих магазинов (Google Play, RuStore и др.) владелец определил требование:
1. Первый распространяемый APK уже должен содержать полнофункциональный раздел «Настройки → Обновления».
2. Обновления проверяются и скачиваются из публичного репозитория GitHub Releases (`https://github.com/sinonhr-prog/mylife-releases`).
3. Установка новой версии выполняется поверх существующей через системный механизм Android с сохранением базы данных, ключей и настроек при явном подтверждении пользователя.

## 2. Архитектурное решение

### 2.1. Узкое сетевое исключение (Scoped Network Exception)
В `AndroidManifest.xml` приложения добавляются разрешения:
- `android.permission.INTERNET`
- `android.permission.REQUEST_INSTALL_PACKAGES`

Действие сетевого разрешения строго ограничивается единственной подсистемой — **клиентом проверки и загрузки релизов** (`UpdateRepository` / `GitHubReleaseClient`).
- Все модули и подсистемы личных данных (`core:storage`, `core:security`, `feature:notes`, `feature:purchases`, `feature:places`, `feature:reminders`, `feature:vault`, экспорт архива `.lifevault`) остаются на 100% автономными и не имеют доступа к сетевым классам или сокетам.
- Запрещены любые сторонние сетевые SDK, аналитика, трекинг, телеметрия, crash-reporting, удалённые шрифты, внешние изображения и фоновый автоматический сбор данных.

### 2.2. Сетевая безопасность и Allowlist доменов
1. Запрещён любой незашифрованный трафик (cleartext/HTTP). В `res/xml/network_security_config.xml` устанавливается:
   `cleartextTrafficPermitted="false"`.
2. Поддерживаются только протоколы TLS v1.2 и TLS v1.3 со стандартной валидацией системных сертификатов Android CA.
3. Сетевой клиент выполняет запросы исключительно к проверенным доменам GitHub:
   - `api.github.com` — запрос последнего релиза через официальный GitHub REST API (`GET /repos/sinonhr-prog/mylife-releases/releases/latest`).
   - `github.com` и `objects.githubusercontent.com` — скачивание активов релиза (APK и метаданных) с CDN.
   - Любые HTTP-перенаправления (301/302) проверяются перед переходом: перенаправление на любой сторонний домен, не входящий в доверенный allowlist, немедленно прерывает загрузку.
4. Токены авторизации GitHub в APK отсутствуют и запрещены; используются только публичные неавторизованные запросы.

### 2.3. Контракт релиза (`update.json` схемы 1)
Каждый официальный релиз на GitHub содержит:
- Файл метаданных `update.json`:
  ```json
  {
    "schemaVersion": 1,
    "applicationId": "local.mylife",
    "versionCode": 2,
    "versionName": "0.2.0",
    "minSdk": 29,
    "assetName": "mylife.apk",
    "sizeBytes": 15728640,
    "sha256": "<64-hex-sha256-digest>",
    "channel": "stable"
  }
  ```
- Файл релиза `mylife.apk`.
- Текстовый файл контрольных сумм `SHA256SUMS`.
- Описание изменений (Release notes) в формате простого безопасного текста (plain text). Рендеринг HTML/WebView запрещён.

### 2.4. Верификация перед установкой
Скачанный во временную приватную область (`context.cacheDir/updates/`) файл APK проходит многоступенчатую проверку перед передачей установщику:
1. **Проверка размера**: фактический размер файла должен точно соответствовать `sizeBytes` из `update.json`.
2. **Проверка целостности**: вычисляется потоковый хэш SHA-256 загруженного файла и сверяется с `sha256` из `update.json`.
3. **Проверка совместимости пакета**: через платформенный `PackageManager` инспектируется скачанный APK:
   - `packageName` совпадает с текущим `applicationId` установленного приложения.
   - `versionCode` строго больше текущего установленного `versionCode` (защита от downgrade).
   - `minSdkVersion` не превышает текущую версию Android устройства.
4. **Проверка криптографической подписи (Certificate Pinning)**:
   - Извлекаются сертификаты подписи скачанного APK (`SigningInfo` / `signatures`).
   - Сертификат подписи сверяется с доверенным отпечатком публичного ключа/сертификата разработчика («Моя жизнь»).
   - Если подпись отсутствует, повреждена или выполнена чужим ключом — файл немедленно удаляется, установка блокируется с понятным сообщением об ошибке.

### 2.5. Установка через Android PackageInstaller
1. Проверяется платформенное разрешение `packageManager.canRequestPackageInstalls()`. Если оно не предоставлено, пользователю выводится пояснение и запускается интент `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES` для текущего пакета.
2. Сессия установки создаётся через `PackageInstaller`:
   - Запись APK в сессию потоком из приватного кэша.
   - Вызов `session.commit(statusReceiver)`.
   - При получении статуса `STATUS_PENDING_USER_ACTION` запускается системный диалог Android для подтверждения обновления пользователем.
3. Отмена установки пользователем оставляет текущую версию приложения полностью функциональной.
4. После завершения сессии (успех или ошибка) временный файл APK удаляется из кэша.

### 2.6. Политика запросов (Rate Limiting и UX)
- Основной режим — проверка по явному действию пользователя (нажатие кнопки «Проверить обновления» в меню Настройки → Обновления).
- Фоновый постоянный polling, постоянные фоновые сервисы и таймеры запрещены.
- Опциональная проверка при старте приложения может быть включена пользователем в настройках; она выполняется с использованием HTTP-кэширования (`If-None-Match` / `If-Modified-Since`) и экспоненциального отката (backoff) при ошибках сети или лимитах GitHub API (403/429).

## 3. Последствия

### Положительные:
- Пользователь всегда может обновить приложение до свежей безопасной версии без сторонних маркетов.
- Сохраняется 100% автономность и конфиденциальность личных записей: ни байта пользовательских данных не покидает устройство.
- Защита от подмены обновлений гарантируется криптографической проверкой подписи APK и сверкой хэша SHA-256.

### Ограничения и риски:
- На уровне ОС Android разрешение `INTERNET` выдаётся всему процессу приложения. Изоляция обеспечивается строгой архитектурой модулей, изоляцией `UpdateRepository` от баз и ключей, и контролем зависимостей (проверяется тестами).
- При выполнении сетевого запроса к GitHub/CDN провайдер сети и сервер видят IP-адрес устройства и стандартные сетевые заголовки HTTP; об этом пользователь честно предупреждается в документации.
- При утере закрытого ключа подписи APK последующие обновления через замену станут невозможны (потребуется переустановка с восстановлением из ручного архива `.lifevault`). Ключ подписи хранится и резервируется владельцем вне репозитория.
