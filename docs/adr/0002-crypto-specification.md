# ADR 0002: Спецификация криптографической защиты, key envelopes и формата архива

Статус: подготовлено для профильного ревью (crypto-design-review), 17.10.2026.

## 1. Контекст

Приложение «Моя жизнь» функционирует строго автономно (без сети) на устройствах Android (minSdk 29). Требуется защита личных записей, файлов и изолированного сейфа от несанкционированного доступа к памяти устройства, резервных копий и дампов, а также обеспечение безопасного переноса через ручной зашифрованный архив `.lifevault`.

## 2. Выбранные проверенные библиотеки и примитивы

В соответствии с правилом запрета собственной криптографии используются строго стандартизированные библиотеки:
1. **Шифрование баз данных**: SQLCipher 4.6.1 (`net.zetetic:sqlcipher-android:4.6.1`).
   - Алгоритм: 256-bit AES-CBC / HMAC-SHA512 (формат страниц SQLCipher v4).
   - Режим журналирования: WAL (`PRAGMA journal_mode=WAL`).
   - Размер страницы: 4096 / 16384 байт (совместимость с 16 KB page alignment Android 15+).
2. **Key Derivation Function (KDF)**: RFC 9106 Argon2id via Bouncy Castle 1.78.1 (`org.bouncycastle:bcprov-jdk18on`).
   - Параметры: `memoryKiB = 65536` (64 MiB), `iterations = 3`, `parallelism = 1`, `outputLengthBytes = 32`.
   - Замеренное время вычисления на целевом runtime (Android 10 API 29): ~1.3 с.
   - Минимально допустимые параметры чтения архивных данных: `memoryKiB <= 131072` (128 MiB), `iterations <= 10`, `parallelism <= 4` для предотвращения DoS-атак перегрузки памяти.
3. **Обёртки ключей (Key Envelopes)**: AES-256-GCM (`AES/GCM/NoPadding`).
   - Ключ: 256 бит (32 байта).
   - Nonce: 96 бит (12 байт), генерируется CSPRNG (`SecureRandom`).
   - Аутентификационный тег: 128 бит (16 байт).
   - Обязательный AAD (Additional Authenticated Data): канонический URI назначения (`version=1;purpose=<purpose>;id=<scope>`), исключающий подмену контекста ключа.
4. **Потоковое шифрование файлов и архива**: Google Tink 1.8.0 / 1.15.0 (`AesGcmHkdfStreaming`).
   - Примитив: HKDF-SHA256 + AES-256-GCM.
   - Размер сегмента: 4096 байт с независимой аутентификацией каждого блока.
   - Защита от усечения и перестановки блоков.
5. **Аппаратное связывание (Hardware Binding)**: `AndroidKeyStore`.
   - Неэкспортируемые мастер-ключи AES-256-GCM с защитой TEE / StrongBox.
   - Авторизация биометрией через `BiometricPrompt.CryptoObject(cipher)`.

## 3. Композиция Key Envelopes и жизненный цикл

### 3.1. Разделение областей (Scopes)
- `main`: основная база `main.db`, ключи файлов и вложений заметок.
- `vault`: изолированная база `vault.db`, ключи секретов и вложений сейфа.
- Области имеют независимые случайные 256-битные ключи базы данных (`DK_main`, `DK_vault`) и независимые аппаратные мастер-ключи Keystore (`mylife_master_main`, `mylife_master_vault`). Открытие главного экрана или меню принудительно аннулирует сессию сейфа.

### 3.2. Вложенная обёртка PIN-пути
1. Пользователь вводит PIN (6 цифр, утверждено владельцем 17.10.2026).
2. Из PIN и случайной соли `Salt_Pin` через Argon2id вычисляется ключ `K_pin`.
3. Внутренняя обёртка: `InnerWrap = AES_GCM_Seal(K_pin, DK, AAD="v=1;p=pin-wrap;id=<scope>")`.
4. Внешняя обёртка: `OuterWrap = AES_GCM_Seal(K_keystore_pin, InnerWrap, AAD="v=1;p=device-pin-wrap;id=<scope>")`.
- Свойство: без аппаратного ключа устройства атакующий с украденным файлом базы не может проверить PIN перебором offline. При утрате устройства или смене прошивки для восстановления используется архив `.lifevault`.

### 3.3. Биометрический путь
- `BioWrap = AES_GCM_Seal(K_keystore_bio, DK, AAD="v=1;p=bio-wrap;id=<scope>")`.
- Ключ `K_keystore_bio` требует успешной аутентификации биометрией через `CryptoObject`.
- При изменении набора биометрических данных в системе (добавление нового пальца) ключ автоматически инвалидируется системой Android, обёртка перестаёт открываться и приложение требует ввод PIN.

### 3.4. Смена PIN
- Процедура: авторизация текущим PIN → расшифровка `DK` в памяти → генерация новой соли `Salt_Pin_new` → Argon2id вычисление `K_pin_new` → запечатывание новых обёрток во временный файл → атомарный `rename` → обнуление промежуточных массивов байт (`Arrays.fill(bytes, 0)`).

## 4. Спецификация архивного формата `.lifevault`

Файл архива содержит:
1. **Заголовок (Header)**:
   - Magic: `4C 49 46 45 56 31 00` ("LIFEV1\0", 7 байт).
   - Версия формата: `0x01` (1 байт).
   - Соль архива `Salt_Archive`: 16 байт CSPRNG.
   - Параметры Argon2id: memoryKiB (4 байта BE), iterations (4 байта BE), parallelism (2 байта BE).
   - Обёртка ключа архива: `ArchiveKeyEnvelope` (AES-256-GCM, 12 байт nonce + 32 байта ciphertext + 16 байт tag), запечатанная ключом, полученным из парольной фразы архива.
   - AAD заголовка: `v=1;p=archive-key;m=<magic>`.
2. **Тело архива (Encrypted Body)**:
   - Зашифрованный через Tink `AesGcmHkdfStreaming` непрерывный поток данных.
   - Внутри потока: канонический архив с манифестом (`manifest.json` со списком файлов и SHA-256), копией `main.db`, `vault.db` и зашифрованных вложений.
3. **Восстановление**:
   - Чтение заголовка и проверка лимитов параметров KDF.
   - Проверка парольной фразы и аутентификационного тега ключа архива.
   - Распаковка во временный staging-каталог с проверкой на path traversal.
   - Создание новых локальных ключей и Keystore-обёрток на целевом устройстве.
   - Атомарная замена рабочей базы данных.

## 5. Выводы и готовность к ревью

Все ключевые примитивы проверены тестами на реальном runtime Android 10 (API 29):
- SQLCipher 4.6.1 + Room: round-trip, защита от неверного ключа, WAL, миграция схемы.
- RFC 9106 Argon2id: эталонный тестовый вектор, замер производительности.
- NIST SP 800-38D AES-256-GCM: эталонный тестовый вектор CAVP Case 16, защита AAD.
- Google Tink Streaming AEAD: потоковое шифрование, обнаружение повреждения и усечения.
- Keystore & Biometrics: генерация ключей, разделение областей `main` / `vault`, `CryptoObject`.
