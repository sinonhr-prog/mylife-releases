# Автоматизация сборки и релизов через Git (GitHub Actions)

В проекте настроен автоматический CI/CD конвейер GitHub Actions ([`.github/workflows/release.yml`](../.github/workflows/release.yml)), который собирает проверенные APK и публикует релизы для встроенного обновления приложения.

---

## 1. Как это работает

```
Разработчик делает git push / git tag
          │
          ▼
GitHub Actions (Ubuntu Runner)
  ├─ 1. Статические проверки (verify-project.mjs)
  ├─ 2. Сборка и запуск unit-тестов (Gradle testDebugUnitTest)
  ├─ 3. Сборка APK (assembleRelease при наличии ключа или assembleDebug)
  ├─ 4. Расчёт SHA-256 и генерация манифеста update.json (схема v1)
  ├─ 5. Сохранение артефактов сборки в Actions Run Artifacts
  └─ 6. Публикация релиза на GitHub Releases
          │
          ▼
«Настройки → Обновления» в приложении на телефоне
  └─ Обнаруживает релиз, скачивает APK, проверяет SHA-256 и устанавливает поверх
```

---

## 2. Подключение удалённого репозитория GitHub

Если удалённый репозиторий ещё не привязан локально, подключите его:

```bash
# Добавление удалённого репозитория
git remote add origin https://github.com/sinonhr-prog/<имя-репозитория>.git

# Проверка подключения
git remote -v
```

---

## 3. Запуск сборки и создания релиза

### Вариант А: По тегу версии (Рекомендуемый способ для релизов)
Создайте тег с версией и отправьте его на GitHub:
```bash
git tag v0.1.0
git push origin v0.1.0
```
GitHub Actions автоматически:
1. Извлечёт версию `0.1.0` и номер сборки.
2. Соберёт `mylife.apk`.
3. Рассчитает SHA-256 хэш и сгенерирует `update.json` и `SHA256SUMS`.
4. Создаст официальный релиз на GitHub с прикреплёнными файлами.

### Вариант Б: При каждом коммите в ветку `main`
При отправке коммитов:
```bash
git push origin main
```
Конвейер соберёт APK, проверит все тесты и прикрепит свежий билд к релизу/артефактам.

### Вариант В: Ручной запуск (Workflow Dispatch)
В браузере на GitHub:
1. Перейдите во вкладку **Actions**.
2. Выберите workflow **Build and Release APK**.
3. Нажмите кнопку **Run workflow** (можно выбрать канал: `stable` или `preview`).

---

## 4. Состав публикуемого релиза

Каждый релиз содержит 3 обязательных файла согласно [ADR 0003](adr/0003-network-exception-and-updates.md):
* **`mylife.apk`** — исполняемый файл приложения для Android.
* **`update.json`** — манифест для встроенного обновлятора приложения:
  ```json
  {
    "schemaVersion": 1,
    "applicationId": "local.mylife",
    "versionCode": 1,
    "versionName": "0.1.0",
    "minSdk": 29,
    "assetName": "mylife.apk",
    "sizeBytes": 53496452,
    "sha256": "5ba195e150b17db8a4190b8aac574b45835744f9780bf04015eb30af97b8f6f1",
    "channel": "stable"
  }
  ```
* **`SHA256SUMS`** — текстовый файл с контрольной суммой для ручной проверки.

---

## 5. Обновление на телефоне

1. Откройте приложение «Моя жизнь» на телефоне.
2. В левом меню ☰ перейдите в **«Настройки» → «Обновления»**.
3. Нажмите **«Проверить обновления»**.
4. Приложение покажет новую версию, список изменений, скачает APK по защищённому каналу, проверит SHA-256 и запустит системную установку без потери ваших локальных данных.
