# База знаний: ошибки и ограничения

## UPD-002 — версия в update.json не соответствует версии внутри APK

- Дата: 17.10.2026; runId: 20261017-sol-updater-followup; узкая диагностика обновлятора по поручению владельца.
- Симптом: на скриншоте Vivo скачанный APK отклонён: версия файла 1 не новее установленной 1. Это происходит после получения метаданных и загрузки, а не при первичной проверке доступности обновления.
- Причина, подтверждённая кодом: workflow вычисляет versionCode из числа commit и передаёт его генератору update.json, но не передаёт его в Gradle. В defaultConfig APK остаются versionCode=1 и versionName=0.1.0. Генератор доверяет отдельным аргументам без сверки конечного APK.
- Действие: подготовить согласованную передачу версии в сборку и генерацию manifest из фактических метаданных APK; защиту от downgrade не ослаблять.
- Результат: скачанный v0.1.7 подтвердил несовпадение 7/1. Старый APK отрицательным CLI-тестом генератора отклонён до записи release-файлов. Новый локальный code 8/name 0.1.8 и metadata совпадают; APK установлен через adb install -r с той же подписью. На Vivo проверка обновлений завершилась состоянием актуальной версии. Это не проверка установки через GitHub/PackageInstaller.
- Профилактика: сравнивать applicationId/versionCode/versionName/minSdk конечного APK и update.json до публикации; проверять тот же артефакт, который распространяется.

## UPD-003 — опубликованный CI debug APK имеет другую подпись

- Дата: 17.10.2026; runId: 20261017-sol-updater-followup.
- Симптом: обновление опубликованным APK не может заменить локально установленное приложение даже после исправления номера версии.
- Причина: apksigner подтвердил разные публичные SHA-256 отпечатки сертификатов установленного APK и скачанного v0.1.7. Новый локальный candidate имеет тот же сертификат, что установленный APK. CI без release secrets использует случайный debug keystore каждого runner.
- Действие: автоматическая публикация debug APK отключена; они остаются только workflow artifacts. Постоянный подписанный канал и конкретная публикация остаются отдельной контрольной точкой, ключи не читаются и не загружаются.
- Результат: подписи трёх готовых APK проверены; защиту ApkVerifier и системную проверку подписи не ослабляли.
- Профилактика: один управляемый ключ подписи для всей цепочки обновлений; перед публикацией сверять фактическую подпись и versionCode конечного APK. Не заменять приложение удалением с потерей данных.

## PUB-001 — auto-review отклонил публичную синхронизацию исходников и harness

Обновление 17.10.2026: владелец дал отдельное явное разрешение на указанный состав публичного source commit («разрешаю, после подготовь передачу для gemini»). Штатный повтор `git push origin HEAD:main` разрешён и завершился успешно, `0752737..84fb5a5`. Обходов не использовали. Это разрешение не публикует APK, ключи, scratch или пользовательские данные и не является real-secrets/release review. Первоначальный отказ ниже сохранён как история.

- Дата: 17.10.2026; runId: 20261017-sol-updater-followup.
- Симптом: выполнение git push origin HEAD:main отклонено автоматической проверкой до запуска.

## UPD-001 — хост release-assets.githubusercontent.com отсутствовал в allowlist, рассинхронизация артефакта APK

- Дата: 17.10.2026; runId: 20261017-152400-gemini-updater-fix; проверка экрана «Обновления» на физическом устройстве Vivo.
- Симптом: при нажатии «Проверить обновления» на физическом устройстве появлялась ошибка: `SecurityException: Хост не входит в доверенный allowlist: release-assets.githubusercontent.com`. После первой попытки исправления ошибка повторилась.
- Диагностика и причины:
  1. При скачивании файлов релиза (`update.json`, `mylife.apk`) GitHub отдает HTTP-редирект (302/303) на CDN-хосты `release-assets.githubusercontent.com` и `objects.githubusercontent.com`. В исходном списке доверенных хостов `allowedHosts` присутствовал только `objects.githubusercontent.com`, а `release-assets.githubusercontent.com` и суффикс `githubusercontent.com` отсутствовали.
  2. В `openRedirectingConnection` обработка кодов редиректа не включала код HTTP 303 (`HTTP_SEE_OTHER`), который возвращают некоторые прокси/CDN GitHub.
  3. Рассинхронизация сборки: бинарный артефакт `app-debug.apk` был собран на несколько секунд раньше, чем были применены правки в исходном коде Kotlin. При анализе содержимого `classes.dex` предыдущего установленного APK строка `release-assets.githubusercontent.com` отсутствовала.
- Исправление:
  1. В `allowedHosts` добавлены `release-assets.githubusercontent.com` и `githubusercontent.com`, а проверка `isAllowed` дополнена поддержкой всех поддоменов `host.endsWith(".$allowed")`.
  2. В `openRedirectingConnection` добавлен код `HttpURLConnection.HTTP_SEE_OTHER` (303).
  3. Выполнена чистая пересборка APK (`:app:assembleDebug`) с проверкой фактического наличия строк в скомпилированном `classes.dex`, и APK заново установлен на устройство через `adb install -r`.
- Проверка: локальный unit-тест валидации URL и обработчика ответов пройден; инспекция DEX подтвердила наличие хостов в скомпилированном коде.
- Профилактика: всегда сверять timestamp сборки APK и фактический байт-код DEX перед отправкой на устройство и тестированием.
