## Шаги

### H03.1 — Реализовать ключи по принятому ADR

Независимые main/vault/files ключи, PIN KDF + device-bound фактор, versioned envelopes.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H03.2 — Сделать вход и сессии

Onboarding, PIN, биометрический путь, Locked/MainUnlocked/VaultUnlocked, обработка неверного PIN.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H03.3 — Обработать lifecycle

Фон/экран/menu из vault закрывают нужную сессию, запросы отменяются; нет secrets в saved state/recents.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H03.4 — Проверить смену PIN и потерю доступа

Атомарная переобёртка, crash на границах записи, invalidated biometrics, честный recovery без bypass.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

## Обязательные критерии закрытия

- **auth-negative**: Неверный PIN/key/tag и неверный scope не выдают секреты.
- **session-isolation**: Main session не открывает vault; lifecycle/process death/menu блокируют доступ.
- **pin-change-crash**: Смена PIN выдерживает прерывания без потери доступной БД.
- **auth-device**: CryptoObject и реальные Keystore-paths проверены на API 29/Vivo.

Точные команды: [BUILD](../BUILD.md) и актуальные README модулей; если задачи ещё нет, создать/проверить её в разрешённом scope, не подставлять несуществующий результат. Ручной критерий получает датированное доказательство устройства/наблюдения. NOT_RUN не допускается как PASS.

## Не входит

Без обходного PIN, auto-wipe, plaintext fallback или заявлений о защите root-устройства.

## Выход и безопасная остановка

Все шаги и requiredChecks отражены в run report, решения подтверждены, CURRENT/STATUS/ERRORS актуальны. Привязать текущие sourceDigest/planDigest и вызвать gate/close. При сбое сохранить фактическое состояние и handoff; не удалять данные и не отмечать этап завершённым. Формат: [PROTOCOL](../PROTOCOL.md).
