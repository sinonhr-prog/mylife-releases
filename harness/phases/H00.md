# H00: Preflight и подтверждение старта

Соответствие общему roadmap: 0 → подготовка 1. Предшественник: нет.

## Вход

Текущий scope владельца, подтверждённая модель, свободный lock и закрытые зависимости. Entry decisions: не требуются. Exit decisions: не требуются. Pending entry блокирует начало, pending exit — закрытие; подготовить результат review до запроса решения.

## Шаги

### H00.1 — Проверить модель, контекст и дерево

Подтверждённый ID/источник, актуальные инструкции, список существующих файлов без чтения секретов; Git status если репозиторий есть.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H00.2 — Проверить инструменты и доступность устройств

JDK/SDK/Gradle/Node/adb обнаружены или отмечены отсутствующими; Android/API Vivo не выдуман; никакой установки.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H00.3 — Проверить пакет и границы

Запустить verify-project, harness validate и harness tests; при доступной браузерной среде сверить утверждённый Фокус. Отсутствие optional preview не скрывать.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H00.4 — Подготовить старт реализации

Список необходимых установок/доступов, план H01–H02 и открытые решения. Сохранить отчёт, CURRENT и handoff; остановиться до поручения реализации.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

## Обязательные критерии закрытия

- **identity-context**: Модель/инструкции/дерево проверены и отражены в санитизированном preflight.
- **toolchain-inventory**: Наличие и отсутствие инструментов/устройств явно зафиксированы; отсутствие SDK здесь не FAIL инвентаризации.
- **planning-checks**: Статические проверки и тесты harness выполнены успешно.
- **handoff-ready**: CURRENT, отчёт и конкретный план следующего шага согласованы между собой.

Точные команды: [BUILD](../BUILD.md) и актуальные README модулей; если задачи ещё нет, создать/проверить её в разрешённом scope, не подставлять несуществующий результат. Ручной критерий получает датированное доказательство устройства/наблюдения. NOT_RUN не допускается как PASS.

## Не входит

Не создавать Android-код, не устанавливать инструменты, не включать реальные данные.

## Выход и безопасная остановка

Все шаги и requiredChecks отражены в run report, решения подтверждены, CURRENT/STATUS/ERRORS актуальны. Привязать текущие sourceDigest/planDigest и вызвать gate/close. При сбое сохранить фактическое состояние и handoff; не удалять данные и не отмечать этап завершённым. Формат: [PROTOCOL](../PROTOCOL.md).
