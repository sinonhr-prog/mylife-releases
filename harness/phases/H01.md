## Шаги

### H01.1 — Закрепить toolchain

После разрешения необходимых установок выбрать совместимые стабильные версии по первичным источникам; записать docs/toolchain.md.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H01.2 — Создать сборочную основу

Wrapper/checksum, version catalog, пять модулей, minSdk 29, AppContainer, минимальная Activity; проверить реальные Gradle tasks.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H01.3 — Настроить проверки и manifest

Unit/lint/format/instrumentation, dependency verification; без INTERNET/телеметрии; initial backup exclusion policy.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

### H01.4 — Проверить запуск

Чистая сборка, test/lint и запуск пустого безопасного приложения на API 29 и Vivo; только synthetic данные.

После шага: соответствующая проверка, evidence и checkpoint. Не начинать зависимый шаг при FAIL/NOT_RUN обязательного условия.

## Обязательные критерии закрытия

- **bootstrap-build**: Wrapper и clean debug build воспроизводятся с зафиксированным toolchain.
- **bootstrap-quality**: Model/unit, lint, format и smoke tests реально выполнены.
- **bootstrap-device**: Activity стартует на API 29 и Vivo; устройства/API указаны.
- **bootstrap-manifest**: Merged manifest без сети/неожиданных exported компонентов; зависимости/лицензии зафиксированы.

Точные команды: [BUILD](../BUILD.md) и актуальные README модулей; если задачи ещё нет, создать/проверить её в разрешённом scope, не подставлять несуществующий результат. Ручной критерий получает датированное доказательство устройства/наблюдения. NOT_RUN не допускается как PASS.

## Не входит

Без функций сейфа, паролей, публикации и незаявленного backend.

## Выход и безопасная остановка

Все шаги и requiredChecks отражены в run report, решения подтверждены, CURRENT/STATUS/ERRORS актуальны. Привязать текущие sourceDigest/planDigest и вызвать gate/close. При сбое сохранить фактическое состояние и handoff; не удалять данные и не отмечать этап завершённым. Формат: [PROTOCOL](../PROTOCOL.md).
