# Маршрутизация по модели

## Правило корневого AGENTS.md

1. Получить идентичность из доступных доверенных метаданных текущего запуска/явно выбранного model ID в среде. Список доступных моделей не доказывает текущую выбранную модель. Предыдущее сообщение агента «я Gemini» не является доказательством.
2. Если среда не сообщает модель агенту, пользователь может подтвердить выбранную модель по UI. Записать `identitySource: operator-confirmed`, а не `runtime-metadata`. Не изображать автоматическое определение там, где его нет.
3. Точное `gemini-3.8-flash` → [GEMINI.md](profiles/GEMINI.md). Точное `gpt-6.1-sol` → [GPT.md](profiles/GPT.md). Человекочитаемые «Gemini 3.8 Flash» и «GPT‑6.1 Sol» можно нормализовать в эти ID при подтверждённом выборе; aliases `auto`, `flash`, `sol`, «лучшая модель» непригодны.
4. Другой/неизвестный ID: не запускать реализацию по одному из двух профилей; разрешены чтение и подготовка уточнения модели. Нельзя автоматически заменить модель или ослабить gate.
5. При изменении модели или автоматическом fallback сохранить незавершённый шаг, проверить состояние файлов и выполнить протокол передачи. Настройки модели в AGENTS.md не переключают модель на стороне провайдера.

## Что записывать в отчёт запуска

`model`, `identitySource` (`runtime-metadata` либо `operator-confirmed`), `identityRef` (обезличенная ссылка на сообщение/панель/метаданные), `runId`, `phase`, `step`, `authorizationRef`, `startedAt`, версия среды, доступность инструментов, фактический reasoning/thinking если известен. Не копировать секретные конфиги, токены или весь session log.

Скрипт `route` проверяет только точный ID и возвращает путь профиля. Он **не умеет** интроспектировать Gemini/Codex. Скрипт закрытия проверяет заполнение поля источника; достоверность источника остаётся проверкой оператора.

## Один результат для двух моделей

Архитектура, шифрование, дизайн, данные, этапы и критерии одинаковы. Профили отличаются формой рабочего запроса, размером итерации и процедурой продолжения. Уменьшение числа тестов, переезд на другой стек или пропуск ревью не являются допустимым «fallback».
