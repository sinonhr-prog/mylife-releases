## 1. Выполненные шаги

- **H05.1 — Сделать согласованный экспорт**:
  - Реализован `LifeVaultArchiveService.kt` в `apps/android/core/storage/src/main/kotlin/local/mylife/core/storage/backup/LifeVaultArchiveService.kt`.
  - Формат заголовка: magic `LIFEV1\0`, version `0x01`, случайная соль 16 байт, параметры Argon2id KDF (64 MiB, t=3, p=1).
  - Мастер-ключ архива генерируется через CSPRNG и запечатывается через AES-256-GCM ключом, полученным из парольной фразы (Argon2id, длина >= 8).
  - Потоковое шифрование содержимого архива через Google Tink Streaming AEAD.
  - Канонический внутренний ZIP: включает `databases/main.db`, `databases/vault.db` (при наличии), зашифрованные вложения `attachments/` и уменьшенные копии `thumbnails/`, ключи БД `keys/keys.bin`, и манифест `manifest.txt` с контрольными суммами SHA-256 всех элементов.

- **H05.2 — Реализовать безопасный импорт**:
  - Проверка формата, версии, валидация параметров Argon2id KDF против DoS-атак (`memoryKiB <= 128 MiB`, `iterations <= 10`, `parallelism <= 4`).
  - Расшифровка потока в изолированный staging-каталог с проверкой целостности.
  - Защита от атак Zip Slip / Path Traversal (запрет `..`, абсолютных путей, проверка canonical path внутри staging).
  - Защита от decompression bomb (лимит до 50 000 файлов и до 500 МБ распакованных данных).
  - Сверка манифеста SHA-256 для каждого извлечённого файла.
  - Атомарный перенос файлов из staging в рабочие каталоги.
  - Генерация свежих локальных обёрток Android Keystore на целевом устройстве с новым 6-значным PIN (`targetKeyEnvelopeManager.restoreKeysWithNewPin(targetPin, mainDbKey, vaultDbKey)`). Полная независимость от старого Keystore.

- **H05.3 — Проверить все неуспешные ветки**:
  - Неверная парольная фраза отклоняется с `GeneralSecurityException` (AEAD BadTag) до изменения каких-либо файлов.
  - Повреждённый или подменённый зашифрованный поток прерывается Tink Streaming AEAD.
  - Усечённый архив (truncated stream) отклоняется.
  - Вредоносные параметры KDF (DoS) отклоняются до запуска вычислений.
  - При любом сбое импорта существующая рабочая база данных и ключи целевого устройства остаются нетронутыми (`restore-atomic`).

- **H05.4 — Восстановить на чистом устройстве**:
  - Полный roundtrip-тест: экспорт на устройстве A -> восстановление на абсолютно чистом устройстве B с новым PIN.
  - Базы данных, вложения и эскизы совпадают байт-в-байт.
  - Базы данных успешно расшифровываются и открываются на устройстве B с новым PIN.
  - Старый PIN устройства A на устройстве B не работает.
