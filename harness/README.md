# Финальный пакет запуска агентов

Версия 1, 16.10.2026. Дизайн утверждён: **«Бумага» + «Фокус»**, дашборд и меню слева. Android-приложение ещё не реализовано. Этот пакет организует разработку; он не запускает модели и не гарантирует безошибочное исполнение.

## Запуск

1. Открыть **эту папку проекта** в выбранной среде с доступом к файлам и терминалу. Выбрать Gemini 3.8 Flash (`gemini-3.8-flash`) либо резервную GPT‑6.1 Sol (`gpt-6.1-sol`). Проверить фактическую модель по UI/метаданным среды. Не подменять другой Flash/Sol без решения владельца.
2. Передать готовый стартовый запрос из [Gemini](prompts/GEMINI_START.md) или [GPT](prompts/GPT_START.md). Он запускает только H00: инвентаризацию, план ближайшего шага, выявление недостающих инструментов и решений. Приложение пока не изменяется.
3. Получить отчёт H00 и подтвердить конкретный диапазон реализации запросом из [EXECUTE.md](prompts/EXECUTE.md). Это разрешение действует на весь указанный диапазон; агент не должен спрашивать заново перед обычными обратимыми действиями.
4. Агент выполняет шаги выбранного этапа, сохраняет контекст после каждого проверенного шага и закрывает этап только через проверку отчёта. Следующий этап начинается только внутри разрешённого диапазона и после выполненных зависимостей.
5. Для смены модели остановить текущего исполнителя, закончить handoff и освободить блокировку. Запустить резервную модель с [RESUME.md](prompts/RESUME.md). Одновременно два исполнителя не пишут в этот checkout.

## Работающий локальный инструмент

Нужен Node.js с поддержкой встроенного test runner и import.meta.dirname (рекомендуется Node 22+). Из корня проекта:

```powershell
node scripts/harness.mjs validate
node scripts/harness.mjs route gemini-3.8-flash
node scripts/harness.mjs route gpt-6.1-sol
node scripts/harness.mjs next
node --test scripts/harness.test.mjs
```

Команды работы с конкретным отчётом и блокировкой описаны в [PROTOCOL.md](PROTOCOL.md). Инструмент не вызывает модель/API, не запускает shell-команды из отчёта, не устанавливает зависимости и не изменяет Android-файлы. Проверяет порядок, обязательные gate-пункты, наличие доказательств, хэши и контрольные решения. Это защита от случайных пропусков, не защита от агента, который намеренно переписывает сам валидатор или фальсифицирует первичные сведения. Подлинность выбора модели и человеческого согласия проверяется средой/владельцем.
