# Основной исполнитель: Gemini 3.8 Flash

Точный ID: `gemini-3.8-flash`. Наличие модели подтверждено [Google](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.8); доступность в аккаунте и среде проверяется при запуске. Профиль — проектная настройка, не доказательство, что любая задача будет выполнена успешно.

## Режим

- Рекомендуемый thinking: `medium` для обычного этапа, `high` для security/migrations/recovery и сложного сбоя, если среда предоставляет эту настройку. Не обещать её изменение без подтверждения среды.
- Один незавершённый шаг карточки за раз. До редактирования: ожидаемое поведение, разрешённые пути, минимальная проверка. Не писать всё приложение одним запросом.
- Держать короткий список действий в CURRENT.md, после проверенного шага сохранять факт, evidence и следующий шаг. В конце этапа — отдельная проверка критериев без добавления новых функций.
- При повторном одинаковом сбое после двух различных обоснованных исправлений: записать гипотезы/доказательства, не делать третий слепой повтор. Попробовать read-only диагностику; если нужен другой исполнитель, подготовить handoff. Это проектная граница для предотвращения циклов, не утверждение о возможностях модели.
- Не менять scope, schema, dependencies или криптографические параметры, чтобы получить зелёный тест. Ошибки окружения отделять от дефектов приложения.

## Формат запроса

Краткие ограничения в начале; затем пути контекста, номер этапа/шага, ожидаемое изменение, критерии и формат отчёта. Использовать один формат разделителей. Излагать выводы и проверки, не запрашивать раскрытие внутренних рассуждений. Для большого приложенного контекста повторить конкретное задание в конце.

## Применение

Прочитать общий [регламент](../PROTOCOL.md), [план](../PLAN.md), текущую карточку phases/ и только её skills из [реестра](../SKILLS.md). Стартовый запрос — [GEMINI_START.md](../prompts/GEMINI_START.md). Все проверки из BUILD.md и TESTING.md обязательны наравне с резервной моделью.

GEMINI.md в корне направляет к общим правилам. Gemini CLI, Antigravity и другие среды могут иметь разные механизмы загрузки инструкций; H00 проверяет фактическое чтение файлов. Наличие файла не доказывает автоматическую загрузку. Если skill discovery недоступен, читать проектный SKILL.md как явную инструкцию, не говорить, что plugin активирован.
