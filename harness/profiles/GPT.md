# Резервный исполнитель: GPT‑6.1 Sol

Точный ID: `gpt-6.1-sol`. Подтверждён [OpenAI](https://developers.openai.com/api/docs/models/gpt-6.1-sol). Используется как резерв или самостоятельный исполнитель того же плана; не имеет права ослаблять требования.

## Режим

- Рекомендуемый reasoning: `high` для реализации; `xhigh` для сложного security review/восстановления, только если доступен в текущей среде. Для простого discovery достаточно `medium`. Это рекомендации оператору, не уже применённые настройки.
- Задавать цель шага, границы, критерии и инструменты; не перегружать промпт копиями всех документов и мелкими универсальными правилами.
- Один незавершённый шаг карточки за раз; допускается закончить несколько последовательных шагов разрешённого этапа в одном сеансе с отдельным checkpoint после каждого. Следующий этап только в пределах выданного разрешения.
- Обычные обратимые детали решать самостоятельно; не превращать каждый файл в новую точку согласования. Существенное изменение требований/защиты и обозначенные ручные gates остаются обязательными.
- Проверки соразмерны изменению, обязательные security/миграционные gates выполняются полностью. Не повторять успешные команды без изменения входов или новой причины.

## Приём работы от Gemini

1. Убедиться, что предыдущий исполнитель остановлен и его блокировка освобождена. Не запускаться параллельно в одном checkout.
2. Прочитать CURRENT.md, handoff последнего запуска, state.json, текущую карточку, соответствующие ошибки и фактический diff/файлы.
3. Сверить хэши доказательств; зелёный gate старого дерева не является проверкой новых файлов. Не начинать с переписывания уже проверенного функционала.
4. Подтвердить model ID, занять блокировку с новым runId, продолжить тот же незавершённый шаг. Требования не пересогласуются без изменения их смысла.
5. После исправления повторить ранее упавшие и затронутые проверки; оформить новые evidence и handoff. Сохранить историю первого запуска.
